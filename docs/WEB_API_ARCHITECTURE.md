# Web API architecture

The project requires TanStack Query for every application API request, with the
HTTP client generated by swagger-typescript-api. This rule comes directly from
the product owner and is recorded in the root AGENTS.md.

## Source of truth and generation

FastAPI publishes `/api/openapi.json` and Swagger UI at `/api/docs`.
`api_contract.py` contains validated response models. Composition input models
live in `models.py`. `openapi.py` exports a discriminated union of all 16 edit
operations from `agent_reference.py`, the same catalog used by MCP. Input fields
with defaults remain optional; serialized output fields are required. Error
responses describe validation, missing resources, conflicts, authentication and
upload limits. Times are integer milliseconds; canvas placement uses fractions.

From the repository root:

```sh
npm --prefix apps/studio run api:generate
npm --prefix apps/studio run api:check
```

The script exports in a disposable data directory without workers or access to
user projects. It generates and formats `src/api/generated/{openapi.json,
client.ts,defaults.json,edit-cases.json}` deterministically. `api:check` generates to a temporary
directory and compares bytes, without editing checked-in output. Backend model
defaults are also generated so optimistic drafts use the same defaults as the
server. Server-produced edit cases verify all 16 optimistic operations; the drift check regenerates these examples too. The npm lockfile pins the generator. CI checks drift on every change.

## Runtime flow

Component → Query/mutation options → generated client → FastAPI.

- `queries.ts`: scoped keys, cache lifetimes, cancellation, polling and pinned
  inspection reads. Private media keys include the project ID; revision history,
  inspections and SRT include their exact revision/job/request. Caption previews
  cache paired raster URLs and foreground bounds by candidate clip + profile,
  including unsaved captions. A replacement is decoded before swapping out the
  last visible image. Position gestures translate that image and its own bounds
  together during the request; new styles/text/sizes never inherit older bounds.
- `mutations.ts`: project creation, uploads, media folders/membership/tags,
  comments, rendering/cancellation and TTS. Components pass captured variables,
  rather than reading mutable form values during an asynchronous request.
- `projectMutations.ts`: per-project planning and write queues, authoritative
  revisions, optimistic layers, rollback and invalidation. Ordinary gestures use
  one operation; compound insertions use an atomic batch.
- `transport.ts`: only error normalization around generated fetch transport.
  HTTP status and validation detail remain available in `ApiRequestError`.
- `queryClient.ts`: finite cache lifetime, focus/reconnect refresh, no retries
  for client errors and no automatic mutation retries. Network/server read
  failures may retry once. Mutation pending/error state is visible in the UI.

The Studio uses the lightweight `/api/state` query for live revision/job updates
instead of an unmanaged EventSource. Polling pauses in background tabs and
follows Query's online state. Explicit media/folder queries also refresh for
changes made by agents. Responses cannot overwrite active optimistic layers.

`/media/*` sources remain native browser streams for seeking, decoding and Range
requests. They do not carry application API state. Caption layout is a Query read
through generated `previewCaption`; its content-addressed `/media/cache/` PNG is
decoded by the browser. Selection appears only with the matching decoded raster.
The displayed snapshot retains its source clip so temporary CSS movement uses
the raster's coordinates, even after Query has projected a newer clip. Late
image events cannot replace the current requested image or another clip.
Raw API PNGs and SRT downloads also use Query; Blob URLs are revoked on
replacement/unmount. POST inspection/raster endpoints are semantically reads.

## Optimistic behavior

Canvas releases retain their local draft until the TanStack edit promise settles;
the draft bridges asynchronous optimistic preparation without a one-frame jump
back. Settlement clears only that gesture, so an older response cannot erase a
newer drag. Failures reveal Query's rolled-back state. Native media synchronization
depends on playback/timing fields, not placement-only clip object changes.

Reversible project edits, canvas/timeline changes, captions, track controls,
folder names/membership, tags and comments appear before acknowledgement.
Project creation and export enqueue show temporary pending records. Temporary
IDs are not actionable; server IDs replace them after success. Uploads and TTS
show mutation progress and expose actual assets only after server validation.
Cancellation can be shown immediately, but the server response wins if a job
already completed.

Cache transactions retain a confirmed base and ordered pending layers. A failed
metadata write removes its own layer, preserving newer independent changes.
Project editing additionally cancels dependent queued edits on failure: a move
cannot be sent after the clip it depends on failed to be created. The cache
rolls back before refetching, so offline rollback does not depend on a successful
read. A 409 never silently retries or replaces another agent's work.

Project projections retain the confirmed revision number; the UI shows Saving
while mutations are pending. Stable client clip/track IDs allow subsequent
queued gestures to address newly inserted objects. `split_clip.new_clip_id` is
optional for this purpose. Undo records confirmed pre-edit revisions. The final
server response always replaces the prediction; renderer validation stays on
the backend. Exports and render inspection wait for pending edits to finish.

### Destructive lifecycle mutations

`writes.deleteJobs` and `writes.deleteProject` optimistically remove list entries
across global/project queue caches, roll back on failure and never retry writes.
`reconcileDeletion` cancels in-flight scoped reads, removes deleted project,
revision/history/media/comment/inspection/caption caches and invalidates lists,
cleanup status and server synchronization. A project deletion is refused while
local editor writes are pending. Server revision checks guard other-client edits.
Project detail forms use `projectWrites`, preserving the same revision queue and
optimistic behavior as timeline editing. All destructive UI dialogs remain open
with errors after a failure. Physical cleanup pending state is read with Query.
Project queues use `GET /api/jobs?project_id=...` so filtering occurs before the
backend's 100-row display limit; bulk deletion is not limited to displayed rows.


### Media inventory and metadata versions

`keys.inventory` is distinct from shared/project `keys.assets(scope)` while remaining
under the assets prefix. `keys.assetUsage(id)` caches reference checks for 5 seconds;
media inventory and usage refresh every 10 seconds. Every API read uses the generated
client with Query cancellation. The owner inventory never implicitly shares sources.

Metadata forms capture `Asset.version`; save and membership removal send the confirmed
version without inventing increments. Polls preserve dirty form drafts; a 409 keeps
that draft and offers explicit reload. Atomic batch tag addition/removal merges at
the server, avoiding destructive whole-list replacement. Shared media mutations are
serialized, optimistically project across every asset-list cache, cancel competing
reads and reconcile authoritative versions. Layered rollback preserves later edits.
Folder deletion moves memberships to root; physical deletion removes sources from
all caches only with guarded server acknowledgement. Usage queries invalidate after
metadata/membership/tag/folder writes; deleted sources' usage entries are purged.
The UI keeps deletion dialogs mounted through optimistic removal to retain failures.
Native players mount only in the single-file management dialog, keeping the library
grid lightweight. Originals/thumbnails remain native /media streams.

### Export-only profiles

`reads.exportPresets()` discovers the backend catalog; `reads.exportPlan(id,
request)` caches read-only POST planning by project/revision and all output
parameters with cancellation. Format/FPS/quality/framing choices stay local until
`writes.render` submits them. Enqueue captures `RenderRequest.output` and the
server resolves `RenderJob.output` (draft cap included), with source warnings.
Only decoded completion metadata proves file dimensions. No project revision is
invented to change output settings. See [export formats](EXPORT_FORMATS.md).

### Script lines and audio takes

`Project.script_lines` stores ordered, stable line IDs, text, and an optional
`audio_asset_id` / `audio_source` / `audio_text` snapshot. The existing
`update_project` operation replaces the list, validates real audio assets, and
synchronizes the legacy `script` string. A changed script-only write clears line
associations; old projects with only plain text stay readable. Initial attachment
does not create timeline clips. Studio's explicit Script and Project media actions
place a ready take on a voiceover track, optionally with one aligned text clip
containing its captured `audio_text`, in one revision-guarded edit batch. When
the take is already on the timeline, the subtitle action adds or synchronizes
the caption without duplicating the audio. Replacing a line take updates
its unambiguous whole-take voiceover clips and scene audio references atomically,
preserving starts/speed/gain and measuring the new duration. Split/trimmed or
shared-line takes require explicit clip edits; overlaps reject without ripple.
Caption timings are not inferred. Studio projects replacement durations only
from validated assets read through Query, then reconciles the server response. Line audio participates in inventory, usage, history,
and deletion protection.

Studio edits use `projectWrites` with confirmed revisions and undo. Dirty drafts
survive polling; concurrent script edits require explicit reconciliation.
Per-line uploads and synthesis use the existing generated client mutations; only
validated assets enter the cache. Bulk synthesis captures text/settings and saves
each result separately, retaining completed takes on failure. By default it fills
missing/outdated AI takes; optional regeneration still preserves manual takes.
Recording requests microphone access only on Record, negotiates a supported MIME
type, releases tracks on stop/cancel/unmount (including late permission replies),
and offers a local preview before upload. Upload probing decodes audio without
container duration, including browser live WebM, to measure its real duration.

`POST /api/projects/{id}/script-lines/{line_id}/audio/replace` uses the same
revision/version guarded project write queue after the new audio has been probed.
It replaces the line and unambiguous whole-take timeline references in one
transaction, then retires the old take from script history and project media.
Exclusive old files are deleted through the durable cleanup outbox. Historical
timeline clips and other collections retain their source for undo, while the old
file stays out of the current project's media grid. Invalid replacements leave
the previous take and project untouched. A cached synthesis result with the
same asset ID remains attached without retiring its own source.

`DELETE /api/projects/{id}/script-lines/{line_id}/audio` is an explicit destructive
lifecycle action, serialized through the same project write queue with confirmed
project revision and asset version. It removes the take and project membership,
scrubs only that line/take's script references and inventory entries from this
project's historical snapshots, then deletes exclusive source files through the
durable cleanup outbox. Other line/timeline references within the project block
the action; shared library/other projects retain their sources. It preserves text
and timeline undo, but removed script audio cannot be restored. The response
reports retention and incomplete physical cleanup. On success Studio evicts
pinned project snapshots before undo, reconciles media caches, and invalidates
history/usage/jobs. Failures roll back the projection and preserve the take.

### Local agent conversations

`chat_contract.py` defines local conversation/settings/context DTOs. Their endpoints
are generated together with the existing contract. `reads.agentChat` polls partial
snapshots through Query and forwards cancellation; `chatWrites` in `mutations.ts`
owns every conversation mutation. Chat versions are independent of project
revisions and prevent late POST/GET responses from rewinding completed text.
Metadata/settings projections use the shared layered cache and confirmed versions.
Sending uses a request ID for deduplication; pending state never invents success.
Applied project revisions invalidate project/history/state reads, whose existing
write layers protect concurrent user edits. Source references contain domain IDs;
the scoped MCP resolves them on the server. Studio's proxy requires a real local
peer for every chat route without trusting forwarded headers.

The standalone local launcher serves those same generated chat endpoints on the
host and streams other requests to an authenticated private Docker engine. Its
server-side `RemoteChatBackend` uses the existing REST contract for scoped MCP
reads and atomic revision-guarded edits. Studio keeps the same Query options,
generated client and cache reconciliation in both deployment modes.

### Studio runtime (TanStack Start)

`apps/studio` applies these generated-client/Query boundaries in TanStack Start. Its route loaders prefetch Query options, and each SSR request owns
its QueryClient. Engine HTTP is restricted to the generated transport and the
explicit server-only proxy in `src/server/backend.server.ts`. The editor route
opts out of SSR while its document and workspace shell remain server-rendered.
Local theme preferences use typed Start server functions through Query.

After contract changes, run `npm --prefix apps/studio run api:generate`. The shared
`make check` and CI gates validate the generated contract, tests and production
build. See `apps/studio/README.md` for runtime and module boundaries.
